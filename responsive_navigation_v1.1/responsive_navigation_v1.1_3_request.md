# responsive_navigation v1.1 要件定義書

## 1. 目的・背景

現行サイトはPC向け固定幅レイアウトを前提としており、スマートフォンでは本文・サイドメニュー・固定幅要素の配置ずれが発生する。v1.1ではPC/タブレット表示を維持し、767px以下のみスマートフォン専用レイアウトへ切り替える。

## 2. 対象範囲

- [MOD] 767px以下の共通レスポンシブCSSを再設計する。
- [ADD] スマートフォン専用ハンバーガーメニューを追加する。
- [MOD] 既存`menu.html`をスマートフォンナビゲーション制御の起点として利用する。
- [KEEP] 768px以上の既存左サイドメニュー構成を維持する。
- [KEEP] 既存公開URL、本文、数式画像、リンク先を維持する。

## 3. 対象外

- 数式画像のLaTeX化。
- 科学技術本文の修正。
- URL変更。
- CMS/SPA化。
- 広告内容そのものの変更。
- 本番FTPへのデプロイ。

## 4. 機能要件

|ID|区分|要件|
|---|---|---|
|REQ-001|[MOD]|767px以下で本文領域を1カラム表示する。|
|REQ-002|[KEEP]|768px以上では現行PC/タブレットレイアウトと左サイドメニューを維持する。|
|REQ-003|[ADD]|767px以下でヘッダー付近にハンバーガーボタンを表示する。|
|REQ-004|[ADD]|ボタン操作で既存`menu.html` iframeをオフキャンバス型メニューとして開閉する。|
|REQ-005|[ADD]|メニュー表示時に背景オーバーレイを表示し、オーバーレイ操作で閉じられる。|
|REQ-006|[ADD]|Escapeキーで開いたメニューを閉じられる。|
|REQ-007|[ADD]|`aria-expanded`と`aria-controls`で開閉状態・対象を表現する。|
|REQ-008|[KEEP]|メニュー項目のリンク先は既存`menu.html`を正本とし、複製管理しない。|
|REQ-009|[MOD]|画像、iframe、表、pre等のスマホ幅超過を抑制する。|
|REQ-010|[ADD]|JavaScript失敗時はハンバーガー化せず、CSSのみの1カラム＋既存メニュー縦配置をフォールバックとして残す。|

## 5. 非機能要件

|ID|区分|要件|
|---|---|---|
|NREQ-001|[KEEP]|静的HTMLサイトとして動作する。|
|NREQ-002|[KEEP]|外部UIライブラリを追加しない。|
|NREQ-003|[MOD]|スマホでページ全体に意図しない横スクロールを発生させない。|
|NREQ-004|[KEEP]|現行Shift_JIS/CP932系HTMLを不用意にUTF-8へ変換しない。|
|NREQ-005|[ADD]|スマホメニュー制御は同一オリジンの親ページDOMのみを操作し、外部入力をHTML挿入しない。|
|NREQ-006|[MOD]|主要ページを375px幅とPC幅で実描画確認する。|

## 6. 制約条件

- スマートフォン判定は`max-width: 767px`。
- PC/タブレット判定は`min-width: 768px`。
- `menu.html`の既存リンク定義をナビゲーション正本として維持する。
- PC版でハンバーガーボタンを表示しない。
- `release_1.0.0`は変更しない。
- 実装は`develop`のみで行う。

## 7. 受入条件

- [ ] 375px幅で本文が1カラム表示される。
- [ ] 375px幅でハンバーガーボタンが表示される。
- [ ] ハンバーガーボタン、オーバーレイ、Escapeでメニューを開閉できる。
- [ ] 375px幅で左サイドメニューが本文下へ常時縦積みされない。
- [ ] 768px以上でハンバーガーボタンが表示されない。
- [ ] 1365px幅で現行左サイドメニュー配置が維持される。
- [ ] メニュー内リンク先が既存URLのままである。
- [ ] JavaScriptエラーが発生しても本文閲覧を阻害しない。
- [ ] `index.html`、`physics/physics.html`、`hydronamics/hydronamics.html`、`fem/fem.html`、`mesh/mesh.html`で確認する。

## 8. 未決事項

なし。実装方式は後続設計で詳細化する。
